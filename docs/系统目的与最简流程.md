## 一、系统为什么存在

用户已有一份需要更新的财务报表附注，以及提供本次数据的工作簿。系统应让原模型读懂两边每个必要格子的实际含义，按同一金标准保存本格身份；程序再把已经唯一对应的来源原值，机械写进新的Excel、Word副本。

识别是核心。程序为识别服务，不能为了旧代码方便读取、旧格式方便拼装或写回方便，改变模型理解原表的过程。正常使用场景是单人在Windows电脑上处理本地财务文档，不应按互联网多租户平台设计系统。

A是待更新的附注，可能来自Word提取出的Excel；B是本次提供数据的工作簿。A、B不是Excel的列名。金标准是统一的财务语义定义，不是业务原值，也不是待填满的字段清单。

## 二、唯一正确路线

1. **原模型识别A、B。** 读取完整上下文和相关金标准，直接给出每个格子对应的金标准及该格自己的身份证。语义、维度、期间、关系和来源的判断，都在A/B识别阶段完成。
2. **程序比较身份证。** 只连接唯一、相同的身份证。不猜、不选、不补、不改写身份，不接受额外的“A位置取B位置”对应关系。
3. **程序机械搬运。** 把已经对应的B原值放入A对应项，形成A′。程序不能重新决定取什么、怎么合并、怎样解释。
4. **程序机械写回。** 利用既有物理位置关联，将A′写入Excel、Word新副本。位置只负责搬运和版式定位，不能代替语义对应。

读取文件、保留表格结构、保存原答复、备份、回读是这些步骤需要的机械工作，不应扩展成另一套语义判断流程。出现未对应项，也不能把候选间的字段差异直接变成模型补交任务。

## 三、几个概念必须分开

| 概念 | 含义 | 例子 |
| --- | --- | --- |
| 金标准槽位 | 格子承载的财务计量含义 | 应收款项账面余额、信用损失准备余额、扣除准备后的账面价值是不同槽位 |
| 维度定义 | 用来描述或区分该槽位的属性 | 实际日期、币种、业务选取范围 |
| 维度实际值 | 原模型从本方原文读出的具体内容 | 某一天、人民币、应收账款中按单项计提的范围 |
| 本格身份证 | 本格的标准对应与模型直接确认的身份信息 | 同一余额槽位在不同业务范围、不同期间角色下不能混为同一事实 |
| 单元格原值 | 本次机械搬运的内容 | 数字、文字、日期、原空白、原公式或按既有依据读取的原公式结果 |
| 物理位置 | 原格在Excel与Word中的位置关系 | 表号、行列、合并起点、既有位置关联 |

标准编号相同不代表所有业务格都可以互填。需要区分的语义必须在原模型的本格识别结果中直接确认，不能等到程序比较时再推断。原值不参与身份的选配或消歧。原值相同也不能证明语义相同。

维度未知不否定已经明确的槽位。空白业务格仍须识别，空白成员名称不等于没有业务位置。未知只影响相应维度和相关动作，不要求把标准中所有字段填满。

## 四、给识别模型什么材料、问什么问题

### 4.1 必须保留的原文

保留本次完整表格、复杂表头和真实合并关系、行名、列名、所属章节和小标题、表前表后的相关注释，以及相关金标准的完整定义。共同信息是否适用于该格，由原模型判断。程序只能保留原文结构和明确引用，不能据行列或文字关键词生成身份。

“完整上下文”要求信息足以理解该格，不是把所有历史记录、无关工作表和整包另一方身份都塞进去。也不能为了压缩材料裁掉必要标题、父项条件、表头或例外。材料需要精简时先消除重复，不删业务事实，不改原文。

复杂表头的文字呈现代码已经内置在项目中：

- `附注更新\表格文字.py` 保留二维网格、明确合并覆盖和原空白。
- `附注更新\Word原文材料.py` 保留原Word文字、表号、原格跨度及已有位置关联，并生成文字网格。

日常文字识别不依赖外部复杂表头技能，不为结构处理另开模型。不能重新压成丢失合并关系的竖线文本、只有数值的列表或需要程序猜含义的位置数组。

### 4.2 问法

已经完成的文字实验使用的问题是：

> 文字表中指定的这个格子是什么意思，和金标准里的哪个槽位最接近？

保持这种直接问法。用户要求识别提示词最多2000个字符。不能通过把一大段指令改名为“材料”绕过限制。原表和标准是原始资料，资料包同样应只保留本次需要的内容和完整依据，消除无关重复。

正式识别须由原模型直接交付每格的标准对应及本格身份证。A、B共用同一金标准与既有保存字段。可以采用清楚的文字、列表、表格或对象交付，不另外规定固定输出模板，不为某份答复增加标签别名、同义转换或解释规则。既有字段名的机械读取不等于程序可以理解并改写自然语言。

已有正确答复优先复用。需要识别时使用 `gpt-6-luna high`，每个必要范围一次，不整表重跑、不自动重答、不追加转换模型、核查模型或复核模型。模型没有交付的内容照实记录，不能由程序从“同上”、共同声明、另列执行安排或另一格取值补出身份。

## 五、程序负责什么

程序负责读取原文件和明确的表格结构，保存原模型直接给出的本格结果，按既定比较要求比较身份证，在唯一相同身份成立后搬运原值，再利用既有位置关联写入新副本并回读。

程序不能重新解释财务含义，不能按公司、名称、金额、年份或位置编写特例，不能在比较阶段选择更接近的含义，不能把同义文字改写为相同身份，不能按数值、来源先后、位置优先级或另列的“A取B”指令消歧。

本次已明确排除比较的 `entity`、`report_scope`、`unit_scale` 实际值仍须照实保存。换期依模型直接确认的期间角色及既定要求机械执行，不能按A旧日期与B日期相等去改角色。名单更新、原值搬运和比较排除要求沿用现有明确要求，不得变成程序自行判断语义的理由。

对无对应、重复身份、缺原文和明确未知，保留原位置、原值、原空白及相关记录，其余已成立的工作继续。错误答复不能覆盖正确结果，混有错误的设置文件不能整份恢复为基线。不能以金额一致、旧日期相等或字段填满新增门槛。
