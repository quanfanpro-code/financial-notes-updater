## 上轮通过后仍存在的问题

| 实际问题 | 本次处理与验证 |
|---|---|
| 只按行范围跳过重复种子，左右并排的小表可能漏掉 | 去重必须有完整行列偏移依据；并排两处及上下12处分别核对 |
| 合并跨出候选范围时未提示关系变化 | 检查相交合并；越过右边界的合并必须进入细读材料 |
| 一个识别词重复多次，被当作多个独立线索 | 部分匹配按不同的识别文字计数；两次、四次重复各有失败反例 |
| 两个相同通用词的完整结构被预筛选排除 | 完整文字入口按登记节点保留，快速与基准一致 |
| 基准比较未完整区分工作表，异常可能仍返回成功 | 身份包含工作表、范围和参照编号；植入第二工作表遗漏，必须返回失败并保留证据 |
| 逐行扫描空白及无关位置，使比较成本过高 | 复用按文字和列建立的行位置，按原窗口查询；优化前后真实A输出除计时外逐项一致 |
| 主程序未正确接收一次性返回的模型结果 | 同时处理完整返回和分段返回；保留原始回执，坏数据、缺结束状态不能被默默当作成功 |
| 已有金额显示格式判断未接入更新清单 | 接回既有判断；仅在同表、同列有唯一可靠格式依据时借用显示格式，不换算给定数值 |
| 启动和资料路径绑定开发者电脑 | 启动查找当前用户的本机Python，缺少时弹窗口；默认选随包公开标准，换目录实测 |
| 核验到冷建库时才核对旧输入清单，迟报过期指纹 | 将全输入核对前置；虚构过期清单必须在读取整簿之前失败 |

部分旧测试仍要求金额单位换算、主体名称作为额外对应门槛，或断言已不再采用的固定分包数量。本轮按已确认的“给定数值原样搬运、主体原文保留但不加门槛、分包不丢不重”修正这些测试。不是通过删掉失败断言来批准旧行为。

## 真实核验的中断与接续

原运行完成五样式及真实A的全部整簿比较后，在冷建库入口因旧输入清单仍登记修复前的读取模块指纹而退出1。失败日志完整保留，不能声称原脚本一次运行成功。

随后通过正式清点入口重新登记当前输入，确认只有已授权修改的读取模块指纹发生变化，全部业务资料仍与旧清单一致。接续检查逐份核对已落盘结果、事先固定的样本指纹及现存原件，重新检查内容覆盖和15项预定要求，再实际执行冷建库、三次新表比较、全量基准及前后指纹检查。新旧索引的三份结构数据逐字节一致；三次新表结果除计时外与已完成结果完全相同。接续退出码0，具体材料在“接续说明.json”及“真实核验接续日志.txt”。

因此，15/15是有证据的接续核验结果，既没有改写失败日志，也没有无故重复整簿比较。核验入口已补前置检查，避免同类旧清单问题再次在长时间计算之后才暴露。

## 本机性能实测

本轮真实A样本有1362个内容格，使用714张小表索引。重复比较三次的中位数为 **4.193秒**；冷建库 **8.48秒**；全量基准比较 **4.394秒**。

原运行开始至接续完成的墙钟时间为 **3117.354秒**，含中断查证时间；其中样式4整簿比较 **2764.59秒**。这个工作簿明细工作表多、重名多，保留全部合理位置后仍有明显计算成本。普通A端用时不能代表此类工作簿，更不能承诺所有新文件都在相同时间完成。

## 仍然存在的边界

- 四张只有通用词“检验”的小表没有足够结构线索，原样输入也可能没有候选；内容按未匹配保留。
- 相似表式会产生多个候选，所属关系和财务含义仍需后续阅读，不能只取排名第一。
- 共用表头缺依据、原映射范围不足等307条资料问题继续登记，没有靠程序猜测补成已确认。
- 结构初筛尚未自动接入主程序的语义识别链路。
- 主窗口仍有章节范围等历史行为，全章节提取及人工修改后回写的新方案尚未完成端到端验收。
- 本次未验证任意服务商的模型兼容性，没有完成整份真实报告从识别到更新的最终业务验收。
- 调试脚本和两处空目录仍在本机，未进入公开包，也未执行删除。
